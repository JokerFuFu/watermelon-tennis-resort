# 西瓜网球度假酒店设计工作台

用于规划网球酒店的中文浏览器应用。通过场地布局、客房配置、投资估算与收益回本测算，把酒店、网球场和配套设施放到同一方案中。无需后端账号。

## Windows / Mac 通用运行（6.3.1）

公开源码：[JokerFuFu/watermelon-tennis-resort](https://github.com/JokerFuFu/watermelon-tennis-resort)。
下载 [Releases](https://github.com/JokerFuFu/watermelon-tennis-resort/releases/latest) 中的 `watermelon-tennis-resort-6.3.1-web.zip`，安装 [Node.js 22或更高版本](https://nodejs.org/)，完整解压后 Windows 双击 `启动酒店.bat`，Mac 双击 `启动酒店.command`。这个运行包已包含构建后的网页，无需 npm、编译器或开发依赖。保持启动窗口运行，Ctrl+C停止。

从源码启动（Windows PowerShell / CMD、Mac 终端命令相同）：

```sh
npm ci
npm run build
npm start -- --open
```

也可双击源码目录的 `启动网页版.bat`（Windows）或 `启动网页版.command`（Mac），自动安装缺失依赖并构建、启动。源码路径建议完整解压到可写目录。

默认使用 `http://127.0.0.1:5173/web`，因此同一台电脑原浏览器在该地址下的数据可以继续使用。端口已占用时不要重复启动；可直接打开原服务，或 `npm start -- --port 5180` 启动独立地址。不同电脑、浏览器或端口的存档分别保存；用界面的JSON导出/导入迁移。代码与运行包不包含你的方案、报价录入、截图或游戏存档。

架构为 React 前端 + Node.js 静态 Web 服务，业务计算在浏览器完成，不需要数据库、后台账号或云端密钥。默认仅本机可访问；有局域网使用需求时可明确运行 `npm start -- --host 0.0.0.0`，再用运行电脑IP访问。该服务没有登录与跨设备同步，现有导出报告与游戏均沿用本地存储。

开发使用 `npm run dev`；构建使用 `npm run build`；运行包使用 `npm run package`。GitHub Actions 在 Windows、macOS、Linux 的 Node.js 22 上运行构建、业务单元测试、因数测试、Web服务测试，并单独验证编译后的浏览器入口。

### Mac 后台开发模式

Mac 上首次使用：先安装 Node.js 与 npm，然后双击项目目录中的 `启动设计工作台.command`。启动器会按需安装依赖、启动本地后台服务并自动在浏览器打开桌面 Web 版。现在可以关闭启动终端窗口，服务由 macOS 管理，并在异常退出后自动重启、登录后自动启动。双击 `启动游戏大厅.command` 可直接打开游戏大厅；需要停止时双击 `停止本机服务.command`。

服务启动后，在运行服务的同一台电脑上打开：

- [桌面 Web 版](http://127.0.0.1:5173/web)：横向工作台，左侧大画布、右侧属性面板，顶部导航始终可见。布局最小宽度为 1100 px；较窄的浏览器面板可横向滚动，仍保持桌面布局。
- [直接查看收益与回本](http://127.0.0.1:5173/web?section=earnings)：打开日、周、平均月和年测算，刷新后仍进入收益页面。
- [直接查看月度经营](http://127.0.0.1:5173/web?section=earnings&earningsView=monthly)：逐月设置房价、入住率、营业天数及设施收费，查看首12月明细和预计首次回本年月。
- [直接查看方案总览](http://127.0.0.1:5173/web?section=overview)：集中查看建设已计投资、营业收入、经营现金结余和回本摘要；启用月度计划后采用首12月结果与首次回本年月，经营缺项保留为待补齐。
- [顾客荒岛求生](http://127.0.0.1:5173/play)：独立游戏页面，提供地形探索、采集、合成、宝箱、商店和金币钻石兑换；不挂载酒店编辑器。
- [管理端荒岛求生](http://127.0.0.1:5173/web?section=play)：游玩并修改当前游戏存档的兑换规则，可返回酒店设计。
- [因数探险家](http://127.0.0.1:5173/factors)：独立因数闯关游戏，从 1 到 100000 顺序寻找全部正因数，提供金币、钻石和道具商店；使用独立存档。
- [手机版](http://127.0.0.1:5173/mobile)：保留原有响应式界面，窄屏时使用竖排布局。根路径 `/` 也保留原有界面。

上述入口依赖运行电脑上的Web服务；公开GitHub仓库与下载页不等于在线托管网站。同一浏览器、同一来源地址下，酒店设计入口共享项目与自动保存数据；游戏入口另用独立存档，不写入酒店方案。

6.3 版新增十项设施管理与操作改进，沿用6.2自定义设施组合库，沿用6.1的布局测量，沿用6.0的15款顾客游戏大厅（14款新游戏及原荒岛求生），沿用5.0的八套功能区组合、阵列复制和适应选区，保留设施多选与批量管理，以及 `section=design`、`rooms`、`budget`、`earnings`、`overview` 和 `section=play` 入口；荒岛游戏仍提供 20 张地图。点击导航会更新地址，刷新、浏览器后退和前进可恢复对应页面；收益页内「年度简算」「月度经营」切换写入 `earningsView=annual` 或 `monthly`，刷新保留该视图。未带有效 `section` 的旧地址仍打开场地设计。本版本号表示工作台功能更新，不表示第三方依赖全部升级到最新版本。

2.4.1 版在页面没有完成加载或工作台无法显示时提供「重新加载此页」。点击后重新加载同一地址，读取同浏览器已保存的方案；恢复功能不清除方案数据，也不保证尚未提交的草稿被保存。本地服务需保持运行。

## 顾客游戏大厅（6.0）

打开 [游戏大厅](http://127.0.0.1:5173/play?game=lobby)，选择数独、扫雷、2048、数字华容道、翻灯；五子棋、中国象棋、围棋、国际象棋、黑白棋、井字棋；斗地主、掼蛋与纸牌接龙。加上原荒岛求生共15款。原 `/play` 无游戏参数仍进入求生，点击其顶部「游戏大厅」切换；酒店管理端通过 `/web?section=play&game=lobby` 打开同一大厅。每个小游戏拥有单独存档、自动保存和JSON导入导出，切换、刷新及浏览器前进后退保留各自进度，酒店和原求生存档独立。

棋类支持同屏双人及基础「电脑走一步」；斗地主与掼蛋是本地人机陪玩。掼蛋为四人搭档单局，包含级牌、逢人配、炸弹和同花顺；围棋按休闲数子，双方可标记死子并确认保存。各玩法和明确边界见 [游戏大厅说明](docs/guest-game-arcade.md)。小游戏专项验收：`npm run test:arcade`，使用独立浏览器会话，结果写入 `test-results/`。

## 因数探险家

双击项目目录中的 `启动因数游戏.command`，或在本机服务启动后打开 [因数探险家](http://127.0.0.1:5173/factors)。这是仅本机可访问的独立入口。每关按正因数数量留格，任意顺序填全且不重复即可通关；金币用于购买提示和随机挑战券，钻石可购买双倍金币券。退出到营地保留进度，自动保存仅属于当前浏览器与来源地址。玩法、奖励和道具价格见 [因数探险家说明](docs/factor-quest.md)。专项验收命令为 `npm run test:factors` 和 `npm run test:factors:browser`，后者需要先启动本机服务。

## 布局测量（6.1）

场地设计画布右上角的「测量标注」为选中且可见的设施标注旋转后的占地宽、深；选中两处可见设施时显示两矩形之间的最短净距。超过8处时标注前8处，完整数据可从「测量清单」查看。单选属性面板可点击「查看尺寸与间距」，多选面板可查看选区测量；清单提供四边用地边距、越界标记、最近设施和隐藏/锁定状态，并支持搜索、选区筛选及CSV导出。导出的是当前筛选范围，算法不提前取整，显示最多三位小数。测量不改变位置或预算；点击定位隐藏设施会恢复其显示。`npm run test:measurements` 用于独立浏览器专项验收。

## 十项设计效率改进（6.3）

1. 设施列表支持按名称、占地或设施工程估算排序，不改动方案的添加顺序。
2. 设施按显示、隐藏、锁定或未锁定状态筛选，可叠加名称与分类。
3. 一键重置搜索、分类、状态及排序。
4. 反选当前匹配结果，保留其他分类里的选择。
5. 匹配结果统计占地面积合计、客房数量及设施工程估算；面积未扣重叠及界外，工程金额不含项目费用、土地和运营。
6. 一次隐藏或显示当前结果，可一次撤销；锁定设施仍能切换显示，预算及面积继续计入。
7. 设计页 Ctrl / ⌘ + D 复制选区，保留原配置，副本显示且解锁，沿用200设施上限。
8. 设计页 Ctrl / ⌘ + A 选择全部显示设施，输入框及弹窗内保留原生行为。
9. 测量清单支持名称、占地及最小边距排序；CSV按当前筛选和排序导出。
10. 复制已保存的组合为独立副本，保留原组合、几何与报价，可恢复上次库修改，沿用20组上限。

查看与筛选不会修改方案或游戏存档。

## 我的设施组合（6.2）

设施库中点击「我的组合」，或选中设施后点击「保存为我的组合」「保存选区组合」。为选区命名并保存，组合独立保留内部布局、尺寸、旋转、房型和报价。支持搜索、重命名、删除及恢复上次库修改，也可导出和导入组合JSON。预览提供「组合近景」与「放置位置」，确认可放后整套加入当前方案，原件不移动、收费项不自动复制，可一次撤销。新设施默认显示且未锁定；组合只包括设施，建材仍在建材工作台管理。组合库最多20组、1MB；来源组合内部重叠或过大时需先调整。库损坏时保留原文并可下载，恢复上次备份前先保存当前数据；其他页面更新库后拒绝覆盖或应用旧预览，关闭重开核对即可。`npm run test:templates` 为专项验收入口。

## 开始设计

1. 默认酒店名称为“西瓜网球度假酒店”，地点为北京。界面与场地采用西瓜主题标志和装饰。桌面 Web 版默认使用铺满窗口的横向工作台，顶部可切换「场地设计」「客房规划」「投资估算」「收益与回本」「方案总览」「荒岛求生」，右侧提供对比、模板、导出、保存和「进入屏幕全屏」按钮。宽度不超过 1250 px 时顶部使用两行布局，保留保存、导出及全屏按钮。手机版及根路径打开后默认进入铺满窗口的设计工作台，右上角退出按钮或左上角菜单可返回项目导航，退出工作台的偏好保存在此浏览器。原示例的杭州地点自动更新为北京，已自定义的地点保留。
2. 从网球度假酒店、精品网球酒店或空白场地模板创建项目，在「项目设置」中修改项目名称、说明和用地尺寸。用地与设施尺寸、设施位置支持 0.01 米步进；面积计算保留小数，界面显示两位小数。桌面 Web 版可通过顶部项目下拉菜单新建或切换项目，点击项目名称旁的设置按钮编辑项目。
3. 在「场地设计」中切换 2D 平面与轴测 3D，通过底部「添加设施」快捷添加酒店客房、网球场、泳池、餐厅会所、景观绿地或停车场，点击「更多设施」打开 51 种空间的设施库，可按分类筛选或搜索；选择「娱乐与游玩」查看 17 种游玩设施，点击「添加到方案」放入场地。「棋牌休闲」快捷按钮或库内同名筛选集中展示棋牌室、麻将包厢、台球室、桌游活动室、阅读休息室和茶艺休闲室；茶艺休闲室的实际分类为「餐饮与社交」。搜索「拍卖」或选择「餐饮与社交」可添加拍卖厅。选中未锁定设施后可拖动，或输入位置、尺寸、楼层、客房数量和参考单价；支持旋转、复制、删除、撤销和重做。
4. 在「客房规划」中调整酒店客房、独栋客房、度假木屋和公寓式客房的标准间、景观房与套房数量。修改总数会按现有比例重新分配，房型合计始终等于客房总数；房型面积超出建筑容量时提示缺口，并可导出客房配置 CSV，面积列保留两位小数。28 / 38 / 58 m² 为示例净面积，用于概念测算。旧方案未配置房型时按全部标准间读取。
5. 在「投资估算」中查看已计预算、规划情景范围与待确认费用。原综合单价保留；点击设施的费用编辑按钮可生成分项草案，按建筑面积、占地面积、客房间数、周长或设备数量计价，也可录入供应商总报价。在「餐饮与日常运营预算」点击「启用并计入运营预算」，可录入饮用水、三餐、日用品和员工消耗，并分别查看建设金额、所选期间运营金额及两者合计。布局检查提示矩形占地重叠、越界和球场概念占地不足，点击提醒中的设施即可定位。「方案对比」（桌面 Web 版位于顶部右侧，原界面位于项目标题旁）支持并排比较最多三个方案的面积、客房、球场、绿地率和投资；可先复制当前方案作为对照。
6. 在「收益与回本」的「年度简算」中按日、周、平均月和年查看营业收入、已填成本与经营现金结余。设置三种房型的每晚价格、停用房数和假设入住率，可填入餐饮、场地租赁、棋牌等其他每日收入；日常消耗沿用已启用的运营费用，额外月支出只填其中未包含的部分。3.0 版可在收益页快捷修改原运营费用的单价与计入状态，启用运营预算仍需单独选择；「编辑日常运营成本」跳转投资页的运营区域。入住率情景显示当前及上下10个百分点的结果，限制在0%至100%，不覆盖保存参数。补齐经营缺项后显示静态回本年限与累计现金回收图；初始投资可使用建设已计金额或手填完整投入。初始房价是示例，未填写的成本不会当成零；具体计算见 [收益与回本说明](docs/earnings-method.md)。切换「月度经营」可分别设置连续12个自然月的房价、入住率、营业天数、其他每日收入和额外固定支出，并为现有非客房设施添加独立收费、直接成本和固定成本。起始月份默认是北京时间当前月的示例，可修改；补齐成本与共用收益参数后查看预计首次回本年月，默认循环预测30年，最多60年。点击「启用月度经营计划」后，总览与方案检查使用该月度计划；未启用时只保存草案。设施收入不再填入其他收入，已在日常费用中计算的成本不再重复填写；详见 [月度经营说明](docs/monthly-plan-design.md)。
7. 方案自动保存在当前浏览器，桌面 Web 版的顶部项目下拉菜单或原界面的「我的项目」可切换已保存方案。顶部「另存为新方案」图标可打开命名窗口，点击「保存副本」保存当前方案的独立副本，原方案保留在项目列表。通过「导出方案」备份 JSON、导入 JSON 恢复编辑，或导出当前布局 SVG 和投资估算 CSV。导出 SVG 前请打开「场地设计」。「方案总览」的「面积核算」展示去重汇总与各设施明细；此处及「场地设计」的「场地信息」均可导出面积明细 CSV。管理工作台的导出菜单提供「收益回本测算 (.csv)」「月度经营计划 (.csv)」和「方案报告 (.html)」，「方案总览」也有「导出方案报告」按钮。月度页的「导出月度测算」另提供逐月参数、设施收费、经营明细与完整预测期的累计回收清单；已保存月度计划时，原收益CSV追加月度数据。荒岛游戏使用页面内的「保存游戏」「导出游戏存档」「导入游戏存档」，不使用酒店方案文件。

项目和设施名称不能留空；每个方案最多支持 200 个设施及另行添加的 500 件建材。导入文件最大为 2 MB，格式或数据无效时保留当前方案。

客房数量按整数保存，失焦后输入框同步显示整数；检查中心搜索优先显示名称直接匹配的设施，客房容量提醒可直接定位对应酒店卡片。

快捷键：`V` 选择、`H` 移动视角、`⌘ / Ctrl + Z` 撤销、`⌘ / Ctrl + Shift + Z` 重做、`⌘ / Ctrl + S` 保存、`⌘ / Ctrl + A` 选择显示设施、`⌘ / Ctrl + D` 复制选区、`Delete` 删除选中设施。在设施名称或数字输入框中使用保存快捷键，会先提交当前输入，再保存方案。数字逐字输入时保留草稿，范围内的有效数值实时更新；超出范围时，在离开输入框或按 `Enter` 后限制到允许范围。空白或无效输入恢复最近的有效值，`Escape` 恢复进入输入框时的数值。3.0 版为尺寸等数字输入显示无效状态及范围修正或整数取整提示，切换建材时重置当前字段草稿。点击另一设施或场地空白处前，也会提交当前名称或数字输入。

2.4 版的「方案检查」可从「方案总览」、设计页「场地信息」或桌面导出菜单打开，检查窗口不占用主导航。窗口汇总布局、客房容量、预算与来源事项，支持分类、设施名称或事项搜索，每次显示 30 项，可继续加载。3.0 版在收益参数已保存时另列收益缺项、年度现金结余不为正或初始投资未填事项，可定位收益页；3.1 版已启用月度计划时改用月度缺项、初始投资及所选预测范围未回收提示。旧项目的示例预览及未启用月度草案不新增月度收益检查。设施相交按每个设施归并，事项数与原始重叠设施对数不同。检查使用当前矩形布局、示例房型面积及已填价格；没有提醒不代表施工或投资审批已通过。点击「显示并定位」会恢复对应隐藏设施的显示，再定位；查看检查窗口本身不修改方案。

方案报告是自包含 HTML，包含完整平面图、面积、客房、预算分项、税口径、价格来源、规划情景范围、未计费用和设施明细；已启用的运营预算另列人数、期间、用量、单价及未报价项，已添加建材另列规格、坐标、组合与采购金额；已保存的收益设置另列四个周期金额、回本年限及缺项，未保存收益设置时提示填写。3.1 版已保存月度计划时另列启用状态、首12月经营明细、设施收费和预计首次回本年月，无需先保存年度收益设置；共用参数仍沿用年度设置或其示例，未填项继续提示。下载后可离线打开，使用浏览器打印菜单或 `⌘ / Ctrl + P` 打印、另存为 PDF。导出本身生成 HTML 文件。报告平面图在内存中显示全部设施和建材，并扩大范围以包含界外设施与建材，不修改已保存的尺寸、位置、可见状态或价格。来源链接可点击，查看离线报告不会自动加载网络资源；打开来源链接需要联网。

点击画布顶部「设施管理」按钮或属性面板中的「设施列表」页签，可按名称、类型或分类查找已添加设施；手机版的列表位于画布下方。点击名称定位到画布中心，定位隐藏设施时会自动恢复显示。设施可锁定或隐藏：锁定后不能编辑属性、客房或价格，也不能移动、旋转或删除，可解锁、切换显示或复制，复制后的设施默认未锁定。隐藏只影响显示，仍参与面积、客房、投资、布局检查和自动排布。

4.2 版可在设施列表逐项勾选，或点击「选择全部结果」加入当前搜索和分类的匹配项；切换分类保留已选项，点击「编辑选区」进入批量面板。在画布上按住 Shift 点击设施可增加或取消选择，普通点击已选成员后拖动可整体移动，点击空白或「清空选择」取消选区。两项以上可按 1、5、10 米步长或自定义横纵位移整体移动，使用六种对齐、横纵均匀排列，以及批量复制、锁定、显示隐藏和删除。任一已选项锁定时先解锁再移动、排列或删除；含隐藏项的选区可通过面板数字移动，不能直接拖动。操作与限制见 [酒店设计 4.2 说明](docs/hotel-design-4.2.md)。

5.0 版可从底部设施库的「功能区组合」选择网球训练、花园木屋、亲子游乐、泳池康养、餐饮聚会、棋牌休闲、商务活动或交通后勤的一整套设施，先查看 2D / 3D 预览、新增客房、面积与工程已计估算，再点击「加入当前方案」。预览默认「全场位置」，可切换「新增区块近景」只看新增设施；这只改变临时展示，不改变实际坐标、面积、价格或加入的方案。选中一个或多个设施后可用「阵列复制」，设置新增行列及横纵间距；每格新增一份完整选区，原件保留且不计入新增份数。新布局避让现有设施、隐藏项及建材组合，不移动原设施或自动扩大用地；无完整空位或超过 200 个设施时整组不加入，成功加入可一次撤销。组合价格为示例，阵列沿用原计价资料；工程估算不包含项目附加费用、土地或运营支出，副本的月度收费需另设。具体配置和边界见 [酒店设计 5.0 说明](docs/hotel-design-5.0.md)。

桌面画布缩放工具中的「适应选区」或批量面板的「查看选区」可放大查看已选可见设施，支持 2D / 3D；仅调整视角，不修改设施或恢复隐藏项。宽屏 Web 顶部点击「5.0」查看版本更新，窄屏 Web 和手机版可通过导出菜单的「版本更新与新功能」打开。

画布支持鼠标中键拖动视角，滚轮以指针位置为中心缩放，缩放范围为 25% 至 1600%。3.0 版在场地建材上使用移动工具或中键拖动时只平移视角，使用选择工具点击才打开建材工作台。「网格吸附」开启后，拖动的起始设施位置按 1 米取整，多选成员使用共同位移保留相对间距；「适应画布」恢复全场视角，保留当前 2D / 3D 模式。

「自动排布」先生成预览，点击「应用排布」后才修改方案，并可撤销。未锁定设施保持尺寸与朝向，按 4 米间距、6 米边界留空排布；锁定设施保持原位，不要求原位置满足 6 米留空。已添加建材和自建组合的外包投影作为固定障碍，不随设施排布移动。锁定设施越界、彼此占地重叠，或当前排布策略未能放下全部设施时，整个原方案保持不变；这不代表不存在其他可行排布。

## 建材与自建作品

2.8 版在「场地设计」底部提供「建材区」，「投资估算」的建材采购面板也可打开。独立建材库提供 32 种常用材料及自定义构件，合计 33 个预设，按砖石混凝土、木材、金属型材、板材保温、屋面地面、管件辅材、袋装散料和门窗构件分类。砖块、木板、工字钢、管材、瓦片、水泥袋、涂料桶和门窗按各自形态绘制；小材料在近景工作台中拼搭，库内规格以毫米显示，属性以米编辑。其他需要的材料可用自定义构件补充，具体预设与参考规格见 [建材区说明](docs/material-builder-design.md)。

工作台支持平面与立体视图、拖动 X / Y、修改宽深高与 Z 高度、旋转、立放、侧立、复制、复制叠放、锁定、隐藏、撤销和重做。Shift 点击画布或勾选材料可多选，输入作品名称后组合；坐标调整移动整组，复制组合保留相对位置并生成独立副本，解散后材料保留。组合内任何材料锁定时，先解锁再移动、旋转、复制或解散。材料显示在总场地，点击可回到建材工作台。手机版通过「建材库」「拼搭」「属性」「作品」切换区域。

每件材料的采购单价初始为未报价；清空单价表示未报价，填 0 表示明确按零计入。数量可按件、最长边米数、最大板面面积或外包体积计算，外包体积不代表空心净料、散料实际体积、重量或施工损耗。采购金额默认不追加到建设预算；核对材料未包含在既有综合价后，可勾选「单列加入建设预算」。启用后已知材料金额单独加入建设合计，不重复追加设计、监理或预备费；未报价与税口径待核实项另行提示。隐藏与锁定材料仍参与面积和采购计算。

导出菜单提供「建材清单 (.csv)」，保存、JSON 导入导出、面积 CSV、投资 CSV、离线报告和方案对比均保留相关数据。建材和组合计入界内总占地，组合取整体外包投影；正常叠放不作为设施相交，不自动增加建筑各层面积、客房或球场。功能用于示意拼搭与采购估算。

## 顾客荒岛求生

4.0 版新增独立荒岛游戏，地形仅用于游戏地图，不改酒店用地。打开 `/play` 可直接游玩；管理工作台的「荒岛求生」页另提供兑换规则编辑和「返回酒店设计」。独立入口不挂载酒店编辑器，也不读取酒店方案存储；入口区分属于前端界面安排，不是账号认证或访问权限系统。

4.1 版保留「碧海湾」「密林岛」「岩峰岛」，新增 17 张地图，共 20 张 18 × 14 格地图，包含深海、沙滩、草地、森林、岩地、淡水与遗迹。新地图以海岸、林地、水域、山岩和遗迹的不同轮廓与地形组合呈现；仍使用现有七类地形和六种物资。点击相邻格、方向按钮或方向键 / WASD 逐格移动，深海不可步行。站到资源格可采集木头、石头、纤维、铁矿、食物和饮水；资源数量会减少，石镐制作完成后才能采集铁矿。制作石斧、石镐、营地、草绳和木筏后，在任意沙滩选择「乘木筏离岛」。任务列表显示采集、工具、营地、草绳、宝箱与离岛进度。

在「下一场荒岛冒险」下点击「浏览全部地图」，查看地图缩略图并选择，再点击「开始新冒险」和「确认开始新冒险」。浏览或预选地图不会改变当前冒险、回合或余额；确认后先备份当前槽位，再开始新冒险，其他两个槽位保留。缩略图使用统一示例种子，实际开局使用新种子，局部地形和资源可能与预览不同。已有存档继续使用保存的地图，不因升级重新生成；所有地图的初始教学路径保留坐标 (6,3) 的纤维资源。

生存状态按行动回合变化，每 24 回合进入下一天，关闭页面时不持续扣减。进食、饮水和休息恢复状态，倒下后可回营地恢复，已采集和已开箱的进度保留。木、银、金宝箱免费开启，每箱只领取一次固定等级奖励。物资商店可购买六种物资，木头、石头、纤维和铁矿可出售；默认 100 金币兑换 1 钻石，1 钻石回兑 80 金币，2 钻石购买恢复补给包。管理页可调整当前存档的汇率，回兑价不得高于购买价；顾客页只查看和使用规则。全部为游戏内货币，与人民币、酒店预算和真实现金兑现无关。

每个浏览器来源提供三个独立存档槽，支持玩家昵称、自动保存、手动保存、刷新恢复和游戏 JSON 导入导出；游戏存档 `version` 为 `1`，不接受酒店方案 JSON。切换存档前先提交昵称，新冒险或导入会先备份当前冒险，「恢复上次冒险」恢复当前槽的备份。昵称尚在输入框中时，保存或导出会先提交有效昵称；空白或无效昵称提示修正。损坏存档保留原始内容，可下载原始文件、选择其他槽或备份后开始新冒险；保存失败时显示提示，不宣称保存成功。浏览器存储无法读取时仍可在内存中试玩并导出。游戏不计入酒店面积、投资或收益，不作为酒店方案的一部分导出；详细规则与存储边界见 [荒岛游戏说明](docs/survival-game-design.md)。

## 数据与估算说明

本版提供概念布局和轴测展示，不提供 CAD / BIM、详细客房平面或施工图。默认项目名称、位置和设施为示例，不代表真实地理场地。

投资金额以人民币计算。未启用分项的旧方案保持原算法：酒店与住宿、餐饮与配套建筑按占地面积 × 楼层 × 综合单价计算，网球场按每片单价计算，泳池与水上娱乐、景观与户外活动、停车与交通按占地面积 × 单价计算。综合单价都是可修改的示例假设，并非北京当地建成报价。

2.2 版可从原综合金额生成土建、面层/装修、机电与设备等分项草案，首次生成保持原金额基线。各分项支持建筑面积、占地面积、客房间数、周长、每设施或手填工程量；此后工程量随对应尺寸或间数变化。草案的拆分比例、价格上下限属于内部规划假设，情景范围不是置信区间。用户可逐项修改单价与来源，也可录入设施总包报价；报价模式只计总报价，不再叠加分项。用户录入报价未经独立核验，超过90天提醒复核。

每项可标记含税、不含税或税口径待确认。不含税且已填税率时加税；未填税率或口径未知时列为待确认，不自动套用税率。项目另列设计、监理、预备费，以及土地、场地与基础设施、市政接入、开业筹备费用。默认设计3%、监理1%、预备10%仅是可调整的规划假设；设计和监理以设施工程为基数，预备费以设施工程、设计、监理、已填场地与接入费用为基数，不以土地或开业筹备为基数。附加费用留空表示未报价且未计入已计合计，填0表示明确按0计入。建设性质与档次只记录范围，不自动套用价格系数。融资及尚未录入的其他运营支出未纳入。设计画布、总览和客房页显示设施工程金额；投资页与方案对比分列建设与所选期间运营合计，CSV包含各项工程量、另加税额、税口径、来源、情景范围和未计费用。

2.7 版新增餐饮与日常运营预算，按采购与消耗成本计算，不是餐饮售价或收入。默认预览为30天、70%假设入住率、每间2位宾客、员工0人。宾客人数可按客房推算或手填平均每日服务人数；手填数替代推算数，不相加，入住房晚仍按总客房 × 假设入住率 × 天数单独计算。饮用水按宾客和员工总人天，宾客三餐与茶饮零食按宾客人天，员工餐单列；洗漱用品、布草洗涤和清洁耗材按入住房晚。员工工资、水电燃气默认按整个期间录入总额，初始单价留空，尚未计入已计金额，不随员工人数自动推算。全部示例用量和单价均可修改，不是北京市场报价。可增删自定义费用，费用列表最多30项；选择「手填总数量」或「整个期间」时不再乘人数或天数。单价清空表示未报价，填0表示明确按0计入，关闭项目的「计入合计」则不纳入金额或缺项；含税、未税与未知税口径及价格来源可逐项填写，用户报价未经独立核验。运营费用不追加建设设计、监理或预备费；综合金额为建设已计费用加所选期间的已录日常消耗，范围只调整建设部分，不等同于全生命周期成本。CSV、离线报告、方案对比与方案检查同时使用已启用的运营数据；对比前应核对各方案的天数、人数、入住率和未报价项。具体口径见 [日常运营预算说明](docs/operating-budget-design.md)。

投资页列出北京官方计价方法、2026年9月材料参考价及类似工程采购案例。材料价、改造预算与维修成交不能直接替代本酒店的新建设施总价，公开资料未直接覆盖全部51类设施。具体依据见 [预算方法说明](docs/pricing-method.md)。

「餐饮与配套建筑」汇总包含室内配套建筑；戏水乐园计入「泳池与水上娱乐」。匹克球场和沙滩排球不计入网球场数量。切换红土、硬地和草地只改变球场外观，造价需按工程范围调整。绿地率统计明确添加的景观绿地和天然活动草坪的界内并集，并扣除非绿地设施、建材及组合外包投影覆盖；其他运动和游玩设施不计入绿地。

面积按矩形设施和建材的 0° / 90° 朝向计算。总用地为用地宽 × 深；界内总占地包含设施、独立建材及组合外包投影，裁切到用地后联合去重，建筑基底仍只统计建筑类设施。未配置用地为总用地减界内去重占地，不自动算作道路或绿地。界内重叠区域为至少两个设施覆盖的区域，每处只计一次，不把建材叠放计作设施重叠；界外占地包含建材与组合并去重。完整设施占地合计仍仅逐项累加设施，含重叠和越界，另列供对照。建筑各层面积仍按每栋完整占地 × 楼层累加，预算工程量不因裁切改变。隐藏和锁定设施及建材均参与统计。各设施明细中的界内面积不能直接相加作为去重总计。具体口径见 [面积方法说明](docs/area-method.md)；这是方案几何计算，真实场地总面积仍以测量结果为准，不作为法规审查结论。

网球双打比赛区域为 23.77 × 10.97 m，模板每片球场的概念占地为 36.58 × 18.29 m，包含缓冲区。尺寸参考 [ITF 网球术语资料](https://www.itftennis.com/en/about-us/organisation/tennis-glossary/)及 [2026 WTA Rulebook，Appendix K](https://www.itftennis.com/media/15607/wta-2026-rulebook.pdf)。实际工程仍需根据场地条件进行专业设计和规范审查。

方案保存在浏览器本地存储中，限定同一浏览器和同一来源地址（协议、主机及端口）；不同端口的开发与预览地址不会共享项目。清除浏览器数据可能删除方案，建议定期导出 JSON。页面加载完成后，设计与导出操作无需联网；可选 Google Fonts 需要网络，无法加载时使用本地备用字体。刷新或重新打开页面仍需本地服务提供页面。

同一来源的多个标签页保存前会读取并合并最新方案列表。当前方案在另一标签页编辑、撤销或重做时，本页没有待保存改动会同步；本页有待保存改动时保留编辑并提示冲突，自动保存停止覆盖。点击「保存」会先把另一页面的版本保留为「冲突备份」，再保存本页版本；也可「另存为新方案」保留本页副本。存储不可用或列表损坏时会提示，未成功保存的编辑仍保留在当前页面，请先导出 JSON；加载损坏列表后，点击保存会替换该不可读列表。

## 本机后台服务

服务只监听 `127.0.0.1:5173`。管理脚本 `node scripts/local-service.mjs start|stop|status` 用于启动、停止或查看；macOS 用户任务为 `local.courtside.studio`，配置位于当前用户 `~/Library/LaunchAgents/`，日志位于项目 `.courtside-server/`。不会清理浏览器存档。移动项目目录后，重新运行启动器以更新路径；停止操作同时禁用登录启动，再次启动会恢复。手动 `npm run dev` 仍可用于开发，但后台服务运行时已占用5173端口，先停止服务再手动启动。
