# 因数探险家

用户已要求开发，并选择独立游戏页面；以其四项玩法为实施依据。

## 玩法

- 独立地址 `/factors`，不挂载酒店编辑器。复用本地 React/Vite 服务。
- 主线从 1 开始，首次通关后才能进入下一个整数。第一版支持到 100000。
- 空格数严格等于该数字的正因数数量，包含 1 和自身；任意顺序填写，必须全部正确、互不重复。空白、非正整数、重复与错误因数有可修改的提示，不扣货币。
- 首次提交正确即结算，每关金币为 `10 + 2 × 因数数目`，钻石为 1，每逢十关额外 2 钻石。重复提交、刷新不能重复领取。
- 通关面板可继续下一关，也可退出至营地；中途退出保留已填答案，返回继续同关。
- 商店：单格提示 10 金币、配对提示 20 金币、随机挑战券 30 金币、双倍金币券 3 钻石。购买只增加背包，使用才消耗。余额不足不扣款，道具无可用目标时不消耗。
- 单格提示填入一个尚未正确填写的因数；空格优先，无空格时替换第一个未锁定错误格。配对提示填入一对乘积为目标数字的因数，已正确填写的成员只补另一项，平方根只占一格。已揭示格锁定，其余格允许修改。
- 随机挑战券给出 2 至 `min(100000, max(20, 主线数字×5))` 内的整数，复用填写规则。金币为对应主线奖励的 75% 向下取整、至少 8；钻石为 1。随机挑战不增加主线进度，未完成挑战保留；继续同一挑战不重复消耗券。
- 双倍金币券在当前未完成关激活，金币翻倍、钻石不变；同一关不能叠加。倍率归属当前主线/随机关，刷新保留，下一新关重新归零。
- 使用独立存档键，自动保存主线、随机关、答案、货币与背包；刷新恢复。退出为回到营地，关闭网页由玩家操作。已有未完成随机挑战时再次使用挑战券只切回原挑战，不消耗。完成100000末关后显示主线全通关，取消下一关按钮，保留营地和随机挑战。

## 页面与视觉

浅蓝纸面、深蓝文字、珊瑚色主要按钮、薄荷与淡紫辅助色。Avenir Next/PingFang SC 系统字体，关卡数字是棋盘主角。桌面主区为填因数棋盘，右侧为奖励与背包；顶部主线关卡轨道展示连续数字与已通关状态。手机纵排，输入格大触控区域。商店、营地、玩法说明使用同一导航。正确提交展示奖励及明确的继续/退出选项；错误就地说明。

## 边界与验收

检查 1、质数、完全平方数、83160（128 个因数）。检查无序答案、空白、重复、0、小数与非因数，防止奖励重复结算。检查余额不足、购买与使用、提示无目标、随机挑战不跳主线、退出与刷新。检查桌面与窄屏无溢出、键盘可操作。`npm run test:factors`、`npm run build`、`npm test` 和 `npm run test:factors:browser` 须退出码0；浏览器脚本在独立会话连续完成前八关及商店/恢复流程，并保存桌面/手机截图。另在可见浏览器确认实际页面、输入和导航。原酒店与游戏大厅入口保持可加载。

## 方案选择

独立根路由最符合用户选择并复用现有运行环境；嵌入酒店导航会混用工作台壳；另建项目增加安装与启动步骤。本次采用独立根路由。目录无 Git 元数据，设计与实现保存在本地，不执行提交。
