# 酒店设计 5.0

在现有酒店方案中增加整套配套设施，或把选区复制为多行多列。所有新增先预览，再由「加入当前方案」提交；预览和取消不修改已保存布局。51种设施库、33个建材预设、20张荒岛地图及既有经营设置保留。

## 功能区组合

从「场地设计」底部设施库点击「功能区组合」，选择以下一套配置：

| 功能区 | 配置 |
| --- | --- |
| 网球训练区 | 4片硬地球场、球员休息区、更衣室 |
| 花园木屋区 | 4栋度假木屋、景观绿地、咖啡馆 |
| 亲子游乐区 | 儿童游乐、戏水、桌游、公共卫生间 |
| 泳池康养区 | 健身房、理疗、瑜伽、泳池 |
| 餐饮聚会区 | 餐厅、咖啡馆、酒吧、户外烧烤 |
| 棋牌休闲区 | 2间麻将包厢、棋牌、台球、茶艺空间 |
| 商务活动区 | 会议、宴会、拍卖厅、游客接待 |
| 交通后勤区 | 停车、充电、洗衣、仓储、卫生间、安保 |

可设置设施间距和用地退界，均为0至1000米的有效数字；默认间距4米、退界6米。预览展示新增设施数、客房数、界内去重占地、完整建筑面积和工程已计估算，支持2D与3D切换。默认「全场位置」，可切换「新增区块近景」只看新增设施；近景只是临时展示，实际坐标、面积、价格及加入方案不变。确认后新增设施成为普通设施，可继续单项或批量编辑。

区块采用最多三列的保守摆放方式，整套避让原有设施、隐藏设施、独立建材及建材组合的外包投影。已有设施的位置、尺寸和重叠状态不被改写，用地也不自动扩大。没有找到完整空位或新增后超过200个设施时，整套不加入；该策略失败不表示不存在其他可行布局。预览期间原方案变更时须核对最新预览，过时结果不会直接覆盖方案。一次加入可用一次撤销恢复。

## 阵列复制

选中一个或多个设施，在属性面板或批量面板点击「阵列复制」。新增行数、列数分别为1至10的整数，横纵净间距及退界为0至1000米；默认1行3列、横纵间距5米、退界6米。每格新增一份完整选区。例如选中2个设施，新增2行3列会新增12个设施，原件不计入新增份数且保留。

复制保留选区内部相对位置、尺寸、朝向和小数坐标，以及房型与报价资料；锁定或隐藏的原件也可复制，副本未锁定且显示。选区内部存在设施重叠时先调整原选区；新阵列作为整块寻找空位，与原布局和建材保持4米外部间距。无法完整摆放或超过200个设施时整次不加入，不缩减数量。

功能区使用可修改的示例单价，阵列使用原件的计价资料；复制报价不等于取得新的供应商报价。预览工程金额仅计新增设施，不包含项目附加费用、土地和运营支出。新增设施不会自动复制月度经营收费项，需到月度经营页另行设置。

## 查看选区与版本说明

桌面画布缩放工具中的「适应选区」，或批量面板的「查看选区」，会调整视角以查看已选可见设施。2D与3D均可用，3D考虑建筑高度；不改变设施坐标、尺寸、预算或显示状态。全选区都隐藏时提示先选择可见设施。

宽屏 Web 顶部的「5.0」按钮和导出菜单的「版本更新与新功能」可打开当前及历史更新说明；窄屏 Web 和手机版使用导出菜单入口。方案JSON版本仍为1，原方案与独立荒岛游戏存档不因升级重置。

## 验收方法

区块与阵列逻辑位于 `src/hotelExpansion.ts`，预览弹窗位于 `src/HotelExpansionDialog.tsx`，版本说明位于 `src/VersionUpdates.tsx`；选区视角由 `src/App.tsx` 和 `src/SiteCanvas.tsx` 接入。领域测试 `src/hotelExpansion.test.ts` 随 `npm test` 执行。开发服务运行后，以独立浏览器会话执行新增功能专项验收：

```sh
npm run test:expansion
```

命令入口为 `scripts/verify-hotel-expansion-50.mjs`，默认访问 `http://127.0.0.1:5173/web`，可用 `COURTSIDE_URL` 指定地址，结果写入 `test-results/`。覆盖预览与取消、完整加入、原布局和建材避让、上限与输入保护、复制资料、月度收费边界、撤销、保存重载、选区视角及手机布局；实际通过情况以当次退出码和输出为准。
