# 4.1 顾客荒岛求生

用户要求顾客能玩的荒岛游戏，并已明确地形放在游戏地图。独立顾客入口 `/play` 只显示游戏，不挂载酒店编辑器；管理端 `/web?section=play` 可进入并调整当前游戏存档的虚拟兑换规则，也可返回酒店设计。`src/main.tsx` 延迟加载对应入口；顾客入口不执行酒店的 `useProject`。游戏存档与酒店方案独立，金币和钻石不计酒店预算，不涉及人民币或真实货币兑现。

保留碧海湾、密林岛和岩峰岛，新增17张岛屿地图，共20张。包含深海、沙滩、草地、森林、岩地、淡水和遗迹。18×14格地图，点击相邻格、方向键/WASD或方向按钮逐格移动，深海不可走；地图轮廓和主要地形由地图类型决定，种子影响局部地形与资源分布。采集木头、石头、纤维、铁矿、食物、饮水，库存和节点数量真实变化；铁矿需先制作石镐。石斧、石镐、营地、草绳、木筏可按配方合成，营地需回起点制作；备好营地与木筏，在沙滩乘筏离岛完成冒险。八项任务显示进度，不要求所有任务均完成后才允许离岛。

新增地图按地形分为以下五类；名称描述现有地形组合，不增加竹材、火山伤害等新物资或规则。

| 地形类别 | 新增地图 |
| --- | --- |
| 海岸 | 椰风海岸、月牙湾、金沙丘、隐秘港湾 |
| 林地 | 竹影岛、翡翠谷、松林山脊、红树林湾 |
| 水域 | 双湖岛、迷雾湿地、河口三角洲、瀑布湖盆 |
| 山岩 | 石礁海湾、赤岩断岸、火山岩岛 |
| 遗迹 | 古城遗岛、宝藏环礁 |

「浏览全部地图」默认折叠，展开后显示20张真实地形缩略图，桌面四列、390px手机两列。点选只预选下一场地图，不改变当前冒险、回合或余额；点击「开始新冒险」后还需「确认开始新冒险」，当前槽位先备份再替换，其他槽位保留。预览统一使用示例种子20261003，开局生成新种子，局部地形与资源可能不同。新地图的可步行陆地连通，初始教学路径保留木头、石头、纤维、食物、饮水和铁矿，纤维仍在(6,3)。旧三张地图的生成规则保留，已有存档按保存的world恢复，不因升级重新生成；游戏JSON版本仍为1。

健康、饥饿、口渴和体力随玩家行动回合变化，每24回合进入下一天，不在关闭页面时消耗。移动、采集、开箱、合成和进食饮水各耗1回合，休息耗2回合；物资交易、换币与钻石补给不推进回合。食物、饮水与休息可恢复属性；倒下可回营地，状态恢复到70、扣除最多10金币，食物饮水至少恢复到2份，保留已采集与已开箱进度，不增加可卖资源。

宝箱有木、银、金三类，每箱免费开启一次，奖励按等级固定：木箱30金币、4木头和2石头；银箱90金币、1钻石和2食物；金箱180金币、2钻石和3铁矿。打开后标记已领取；不以真钱或付费抽奖开箱。奖励或库存达到上限、体力不足时整次动作失败，原存档保持不变。

默认兑换规则：100金币兑换1钻石，1钻石回兑80金币。仅为可调整的游戏规则，购买价为1至1000000的整数，回兑价为0至购买价的整数，余额必须足够，单次交易数量为1至9999的整数。物资商店出售木头、石头、纤维、铁矿、食物和饮水，前四项可回卖，食物饮水不可出售。2钻石补给恢复健康40、体力30、饱食和水分各15，均不超过100。物资买卖、钻石补给可消耗余额，失败不扣款，不允许负数、NaN、重复开箱或批量点击超支。管理端可以修改当前存档的规则，顾客页仅查看和使用规则；不是统一配置下发或真正的账户权限限制。

每个浏览器来源提供3个独立存档槽与玩家昵称；自动保存、手动保存、游戏JSON导入导出、刷新恢复。游戏JSON的`version`为1，与酒店方案格式不同，导入最大500KB。昵称为1至24个字符；保存、导出和切换存档前先提交当前有效昵称，无效时提示而不替换原昵称。每次新冒险或导入先备份当前存档，可恢复最近一次备份；备份仍损坏时可下载原始文件。损坏存档保留原始数据并停止覆盖，可下载原始存档、切换其他槽或明确开始新冒险；备份失败时不替换原档。

存档键为`courtside-survival-slot-1-v1`至`courtside-survival-slot-3-v1`，备份键为`courtside-survival-backup-1-v1`至`courtside-survival-backup-3-v1`，活跃槽位键为`courtside-survival-active-slot-v1`。保存后回读验证；存储配额不足或写入失败显示未保存提示，当前进度可导出。存储无法读取时可在内存中试玩并导出，不宣称已保存。同源多个页面保存前检查当前槽的版本，自动保存遇冲突停止覆盖，手动保存先备份另一版本；没有未保存改动时同步另一页面的有效存档。清除浏览器数据会删除存档，导出的文件需自行保存。不会把游戏字段写入酒店Project、预算、面积或收益，也不把游戏键盘操作传给酒店的撤销或保存；管理端顶部保存及导出仍对应酒店方案，游戏操作使用页内按钮。

顾客页适配390px手机与桌面，提供操作指南、任务进度、状态条、背包、商店和兑换区。分享入口只是本地服务地址，不是已公开托管或真正账户权限系统。六项管理导航在宽度不超过1250px时使用112px高的两行顶部，画布高度同步适配，保留保存/导出/全屏按钮；按需加载游戏及地图，保留原所有规划功能。

验收包括完整采集→合成→离岛流程、地图阻挡、资源耗尽、恢复属性、一次性宝箱、购买/出售/换币精算与失败不扣款、连续操作不超支、3槽独立、导入验证和损坏存档保护、两次刷新、顾客入口不读取酒店存储、酒店数据不变、手机布局及必要旧功能回归。

域模型位于`src/survivalTypes.ts`和`src/survival.ts`，新增地图轮廓与生成逻辑位于`src/islandMaps.ts`，存档逻辑位于`src/survivalStorage.ts`和`src/useSurvivalGame.ts`，页面与地图位于`src/SurvivalGamePage.tsx`和`src/IslandGameMap.tsx`，地图目录与缩略图位于`src/IslandMapGallery.tsx`。领域与存档测试随`npm test`执行，包含`src/islandMaps.test.ts`；开发服务运行后，`npm run test:survival`在独立浏览器会话执行游戏专项验收，`npm run test:maps`通过`scripts/verify-island-expansion.mjs`检查地图目录、预选与确认开局、备份恢复、保存重载、酒店数据隔离及手机布局，默认访问`http://127.0.0.1:5173/web`并检查`/play`。另用`COURTSIDE_URL`指定其他服务地址，输出写入`test-results/`。验收范围不等于已通过结论，实际结果以当次命令退出码和输出为准。
